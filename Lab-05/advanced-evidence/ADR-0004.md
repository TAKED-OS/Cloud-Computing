# ADR-0004. Размещение базы приложения

## Контекст

В ЛР3 PostgreSQL находилась на отдельном EC2 в приватной подсети. В ЛР5 проверена миграция на приватную RDS с сохранением DNS-имени db.timecapsule.internal.

## Решение

В учебной конфигурации использовать RDS PostgreSQL Single-AZ, подключение по TLS и доступ только из группы безопасности приложения. Имя db.timecapsule.internal — CNAME на endpoint RDS во время миграции. Управление резервными копиями и обслуживанием передаётся RDS, приложение отвечает за схему, права пользователя и обработку ошибок подключения.

## Альтернативы

| Вариант | Последствия |
|---|---|
| PostgreSQL на EC2 | Полный контроль над настройками, самостоятельные обновления и восстановление |
| RDS Single-AZ | Управляемые бэкапы и обслуживание, простои при некоторых событиях одной зоны |
| RDS Multi-AZ | Резервный экземпляр и переключение, выше расход ресурсов |
| Aurora PostgreSQL | Управляемое распределённое хранилище и иная модель затрат, для этого эксперимента не требуется |

## Ограничения прогона

Free Plan ранее отклонил семь дней хранения. Для миграции и проверки Scheduler использован один день. После проверки временный экземпляр удаляется, а исходная запись A восстанавливается.
