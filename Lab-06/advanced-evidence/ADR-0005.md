# ADR-0005. Хранение PHP-сессий

## Контекст

ALB распределяет запросы между экземплярами приложения. При хранении сессии в файле следующий запрос может попасть на другой узел, который не знает пользователя.

## Решение

Хранить PHP-сессии в DynamoDB On-demand. Обработчик AWS SDK использует ключ String id и числовое поле expires для TTL. Роль EC2 получает GetItem, PutItem, UpdateItem и DeleteItem для выделенной таблицы.

## Альтернативы

| Хранилище | Последствия |
|---|---|
| Локальные файлы и привязка запросов к узлу | Мало инфраструктуры. При отказе или замене узла сессия теряется |
| Таблица в RDS | Совместно с данными приложения, но запросы сессий используют подключения PostgreSQL |
| DynamoDB | Сессия доступна любому узлу, истёкшие элементы удаляются через TTL |

## Что проверено

Одна авторизованная сессия сохранилась на двух узлах ASG через ALB. Использовалась изолированная PostgreSQL на EC2. В отдельном прогоне CloudWatch подтвердил рост 2 → 4 и снижение 4 → 3. Сессия оставалась авторизованной при снижении.
