# ADR-0006. Фоновые задачи TimeCapsule

В синхронной версии запрос Seal capsule ждёт имитацию отправки письма. При открытии по HTTP просроченные капсулы зависят от первого визита пользователя.

Принято вынести уведомление о запечатывании в SNS, очередь SQS и Lambda; открытие по времени запускает EventBridge Scheduler. Обработчик публикует результат открытия через успешное асинхронное назначение Lambda. PostgreSQL хранит идентификатор события и запись уведомления в одной транзакции. Повторная доставка не добавляет второе уведомление.

| Вариант | Последствия |
|---|---|
| Синхронное выполнение на веб-сервере | Меньше компонентов, но запрос ждёт обработчик. Без посещений открытие может задерживаться |
| Фоновый worker на EC2 | Можно контролировать длительно живущий процесс. Нужны отдельный сервис, мониторинг и обслуживание |
| Lambda, SNS, SQS и Scheduler | Буферизация, повторные попытки и независимый запуск по времени. Нужны ограничение параллельных подключений к БД и обработка повторов |

В эксперименте использована изолированная PostgreSQL на EC2 с TLS. Успешное назначение подтверждено подписанной SQS-очередью. Фактическая доставка email в этом прогоне не проверялась.
